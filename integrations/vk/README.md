# Новости сайта → стена vk.ru/scrapmehi

Независимый бот для **Cloudflare Workers Free**. Читает только открытый
`https://maxfixglitch.github.io/ScrapMecanicNowosti/data/news.json`.
Доступ к GitHub или репозиторию сайту/боту для работы не нужен. Соединять Cloudflare
с GitHub не требуется. Для установки достаточно скопировать эту папку.

**Статус: код подготовлен, но не развёрнут. Реальная публикация ВК не проверена:**
для неё владелец должен настроить Cloudflare и ключ сообщества. Локальные тесты
используют имитацию API, а не настоящую стену.

## Что получится

- Раз в час проверяет ленту; сайт получает новости из Steam раз в 6 часов,
  поэтому мгновенную доставку бот не гарантирует.
- В первый успешный запуск **ничего не публикует**: запоминает архив.
- Затем публикует новые переведённые новости от имени **scrapmehi**,
  от старых к новым, не более трёх за запуск.
- Заголовок, русский текст с абзацами и списками, ссылка на конкретную новость.
  Длинный текст сокращается примерно до 10 000 символов; полный — на сайте.
- **Первая версия без загрузки фото/видео в ВК.** Превью ссылки зависит от ВК.
  Методы загрузки медиа могут требовать других разрешений/типа ключа;
  пользовательский ключ с широкими правами ради картинок не запрашиваем.
- Непереведённые записи ждут перевода. Изменения уже опубликованных патчей
  повторно не публикуются и пост на стене не редактируют.
- Старые записи, впервые обнаруженные после подключения, но датированные не
  позднее самой свежей записи стартового архива, не публикуются.
- Бот не читает и не меняет твои собственные посты в группе.

Бесплатный тариф Workers поддерживает SQLite Durable Objects, где хранится история.
Платный тариф включать не нужно. У сервиса есть бесплатные лимиты, которые могут
меняться: [Workers](https://developers.cloudflare.com/workers/platform/limits/),
[Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/).
Обычная проверка раз в час — небольшая нагрузка, но это не обещание бесплатности навсегда.

## Что должен сделать владелец

### 1. Cloudflare

Создать учётную запись на https://dash.cloudflare.com/ и выбрать **Workers Free**.
Домен покупать и подключать сайт не требуется: у бота будет служебный адрес
`…workers.dev`. Не подключать платный тариф, если интерфейс его предлагает.

### 2. Ключ именно сообщества ВК

В группе **scrapmehi** открыть **Управление → Работа с API → Ключи доступа →
Создать ключ** (названия пунктов могут отличаться). Нужны права на управление
стеной/публикацию. Если такой возможности или права нет, **остановиться и проверить
доступность API с поддержкой ВК** — не выдавать боту пароль от аккаунта и не брать
чужой ключ/обходное приложение.

Ключ не присылать в чат, не вставлять в `worker.mjs`, `wrangler.jsonc`, сайт или Git.
ВК API должен разрешать `groups.getById` и `wall.post` для этого ключа.
Фактическую доступность проверяем при подключении: одной ссылки на группу недостаточно.

### 3. Загрузка бота без GitHub

**Windows 11, если секреты уже сохранены в панели Cloudflare:** установите
[Node.js LTS](https://nodejs.org/), распакуйте папку бота целиком и запустите
[`install-windows.cmd`](install-windows.cmd). Пошаговая инструкция —
[`WINDOWS.txt`](WINDOWS.txt). Установщик использует закреплённую версию официальной
утилиты `wrangler@4.168.0`, открывает вход в Cloudflare и выполняет
`deploy --keep-vars` в существующее приложение `scrapmehi-news`. Секреты не
запрашиваются; уже сохранённые секреты и переменные сохраняются. При повторной
установке существующего бота не удаляйте его память. Установщик включает расписание:
после первой инициализации новые новости могут публиковаться автоматически.
Установщик использует только ASCII и буквальные CRLF, которые сохраняются также
в GitHub-архивах исходников через `.gitattributes`. Сообщения установщика на английском:
`Continue?` означает «Продолжить?», Y — да, N — нет. Проверка формата входит в тесты.
Сам `.cmd` не запускался на Windows в среде разработки (здесь Linux).

**Другие системы / ручная установка:**

Этот шаг технический; его можно выполнить вместе с помощником, не раскрывая ключ.
Потребуется Node.js LTS на компьютере и копия этой папки.
Открыть терминал **в папке `integrations/vk`**:

```sh
npx wrangler@4 login
npx wrangler@4 deploy
npx wrangler@4 secret put VK_TOKEN
npx wrangler@4 secret put ADMIN_SECRET
```

`login` открывает вход в Cloudflare в браузере. В первом `secret put` вставить ключ
сообщества в скрытый запрос терминала, не в команду. Во втором — новый случайный
пароль (не пароль ВК), сгенерированный менеджером паролей, не короче 32 символов.
Сохранить его: он защищает служебные команды бота. Авторизация GitHub не нужна.

До добавления ключа запланированные проверки завершатся ошибкой **без публикаций**.
После добавления ключа первый успешный запуск запомнит весь текущий архив.
Для немедленной инициализации можно вызвать защищённый `POST /run` (ниже).
Если не вызывать, это произойдёт при ближайшем часовом запуске.

Не переименовывать Durable Object `scrapmehi-v1`, не удалять историю и не создавать
копии бота для той же группы: история публикаций должна оставаться единой.

### 4. Проверка

В Cloudflare → Worker → **Logs / Observability** видны ошибки запланированных запусков.
Автоматические уведомления владельцу не настраиваются этим кодом.
Подробный результат доступен через защищённый `GET /status`.

Пример команд для bash (Linux/macOS/Git Bash). Секрет вводится скрыто, не попадает
в историю команд. Не публикуйте вывод с секретами и не используйте `curl -v`.

```sh
read -rsp 'Служебный пароль бота: ' BOT_ADMIN_SECRET; echo
read -rp 'Адрес Worker (https://…workers.dev): ' BOT_URL
# Пароль передаём curl через stdin, а не аргументы процесса.
printf 'header = "Authorization: Bearer %s"\n' "$BOT_ADMIN_SECRET" | curl --config - "$BOT_URL/status"
# Инициализация/проверка С РЕАЛЬНОЙ публикацией новых новостей после инициализации:
printf 'header = "Authorization: Bearer %s"\n' "$BOT_ADMIN_SECRET" | curl --config - -X POST "$BOT_URL/run"
unset BOT_ADMIN_SECRET
```

Первый `/run` должен вернуть `initialized: true`, `posted: 0`, число архивных
записей. Не следует ожидать тестового поста на стене: архив намеренно не публикуется.
Реальную публикацию можно проверить на следующей новой новости. Для отдельного
теста лучше использовать отдельную тестовую группу/установку, не основную стену.

## Если отправка оборвалась: защита от дублей

История хранится в одном SQLite Durable Object; вызовы выполняются последовательно.
Перед запросом `wall.post` сохраняется `pending`. При успехе записывается `post_id`.
В API передаётся также стабильный `guid`, но только на него не полагаемся:
защита от повторов на стороне ВК ограничена по времени.

Если API вернул ошибку/оборвалась сеть или запись результата не сохранилась,
**все последующие публикации приостанавливаются**. Это безопаснее слепого повтора:
ВК мог уже опубликовать пост до обрыва соединения. Автоматического повтора нет даже
при явном отказе — потребуется проверка. `/status` покажет `pending.gid` и заголовок.

Проверить стену группы, устранить причину (например, обновить ключ), после чего
вызвать защищённый `POST /resolve` с JSON:

```json
{"gid":"ИДЕНТИФИКАТОР_ИЗ_STATUS", "action":"published"}
```

- `published`: пост уже есть на стене, запомнить и не повторять.
- `skip`: не публиковать эту новость.
- `retry`: разрешить повтор на следующем запуске — **только после проверки, что
  пост точно отсутствует**. Иначе возможен дубль.

Пример (используя скрытый ввод пароля из раздела выше):

```sh
printf 'header = "Authorization: Bearer %s"\n' "$BOT_ADMIN_SECRET" | \
  curl --config - -X POST "$BOT_URL/resolve" -H 'Content-Type: application/json' \
  --data '{"gid":"ИДЕНТИФИКАТОР_ИЗ_STATUS","action":"published"}'
unset BOT_ADMIN_SECRET
```

Ошибки API сохраняются только как числовой код: ВК может включать токен в полный
ответ ошибки, поэтому сырые ответы не логируются.

## Остановить и отключить

Для временной остановки удалить расписание в Cloudflare → Worker → Settings →
Triggers → Cron Triggers. Защищённый `/run` всё ещё сможет запускать отправку.
Для полной остановки отозвать ключ в ВК и удалить секрет `VK_TOKEN` в Cloudflare.
Если ключ утёк — немедленно отозвать его в группе и создать новый.

## Локальная проверка без ключей

```sh
node --test integrations/vk/worker.test.mjs
```

Запускать из корня проекта. Никаких внешних запросов, публикаций и платных сервисов
эти тесты не используют. Они не доказывают, что ВК примет реальный ключ.
